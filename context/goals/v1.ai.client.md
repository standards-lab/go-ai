## Task brief · design

```
Problem       go-ai is built from spike-ai-pipeline-client v0.4.0, which predates the
              construction-and-execution standard and docproc's layers note. The library
              and infer tasks need one reviewed design to build to.
Behaviors     1. A Fable 5.2 evaluation of the spike opens the review: each issue and
                 simplification against the full architecture standards, the layers
                 note's go-ai surface, and Cerebro's requirements, marked kept, changed,
                 or dropped, with a reason.
              2. The review states go-ai's base module as signatures: the root package
                 and its name, construction and Config, retry policy, the API error,
                 Generate, GenerateStream with its accumulator, Embed, Transcribe, the
                 /models listing, the Open Responses protocol, and the three formats.
                 Every name the layers note lists maps to exactly one go-ai name.
              3. Each docinfer and Cerebro request gets a decision and an owning task
                 (library, infer, or acceptance): a reopenable transcription clip in
                 the retry loop; Retry-After on the API error; per-call timeout and
                 cancellation by context; the consumer key header; Embed batching;
                 relayable stream events; the live-gateway retry proof as acceptance's.
              4. Module layout and dependency line: the base module on the standard
                 library alone, and how the check holds it there; the nested infer
                 module, its requirements, and its four subcommands; the tag scheme
                 (root and tools/infer) with the first tag of each.
              5. Rejected alternatives with reasons: openai-go, anthropic-sdk-go, and
                 anything else the review rules out.
              6. go-ai's standards file gains its judgement calls, one line each, each
                 with its architecture page; the spike's three client rules are carried
                 over or changed.
              7. A per-package change list from the spike, and pending edits that
                 sharpen the library, infer, and acceptance task entries.

              go-ai surface (one-to-one name map); the check
Slices        1 Fable evaluation: findings with keep/change/drop
              2 the base module's surface and the requests answered
              3 module layout, dependency line, tags, infer's module
              4 change list, standards judgement calls, pending edits
Out of scope  code; the harness-session surface; the gateway; docinfer's failure
              mapping; infer's flags
```

## Decisions

- design: start found go-ai current (`mise run currency`), so no plan round opened; the brief
  approved at plan stands.

- plan: go-ai starts from a fresh `init`; the library task ports spike-ai-pipeline-client
  v0.4.0, whose tags sit under another module path and would collide with go-ai's.
- plan: init ships a check-only CI workflow, so the merge's check wait works from the first pull
  request; the release workflow comes with the library task.
- plan: `design` settles infer's nested module, its requirements, and its four subcommands (chat,
  embed, transcribe, models); flags and output wait for the infer task.
- plan: the retry proof against the live gateway (429, 503, Retry-After) is acceptance's, waiting
  on spike-model-gateway; the library task's release doesn't wait on the gateway.
- plan: rejected a vendor SDK (openai-go, anthropic-sdk-go) as the client: none covers all three
  wire formats, openai-go failed minimal-footprint (spike-harness-driver findings.md), and a
  provider enters a base module only through a sub-module (dependencies.md, "No provider in a
  base").
